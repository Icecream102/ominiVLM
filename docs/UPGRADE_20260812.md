# MiniMind-V 训练岗补强升级报告（2026-08-12 下午）

本轮针对“互联网大厂多模态大模型算法训练岗”面试要求做了四块补强：
评测广度、评测口径、数据工程、RLHF 奖励信号。全部实验在单张
RTX 4090 D（24GB）上完成，无分布式依赖。

## 1. 评测口径：官方 METEOR 补齐

此前官方 COCOEvalCap 只有 BLEU/ROUGE-L/CIDEr，METEOR 因
pycocoevalcap 1.2 的解析器与新版 JVM 输出不兼容而缺失。修复了
`meteor-1.5.jar` 的 Python wrapper（输入消毒 + 容错解析），
**10 个检查点的官方四指标全部补齐**（val2017 全量 5000 张）：

| 检查点 | BLEU-4 | ROUGE-L | CIDEr | METEOR |
|---|---:|---:|---:|---:|
| Pretrain | 0.0250 | 0.2160 | 0.0063 | 0.1483 |
| SFT | 0.0237 | 0.2136 | 0.0058 | 0.1491 |
| GRPO 原版 | 0.0067 | 0.1517 | 0.0002 | 0.1023 |
| GRPO fix2 | **0.0266** | 0.2159 | 0.0036 | **0.1529** |
| Qwen3B LoRA | 0.2566 | 0.4542 | 0.8364 | 0.2647 |

GRPO fix2 的 METEOR（0.1529）同样超过 SFT（0.1491），修复链在
四个官方指标上一致成立。

## 2. 评测广度：OK-VQA 与 POPE 幻觉基准

### OK-VQA（知识型 VQA，val2014 全量 5046 题）

| 模型 | 准确率 |
|---|---:|
| 65M SFT（无 VQA 训练） | 0.0% |
| 65M GRPO fix2（无 VQA 训练） | 0.0% |
| **Qwen2.5-VL-3B + LoRA** | **38.5%** |
| 65M 最终多任务模型 | 3.2% |

### POPE 幻觉（COCO2017 val2017 构造，500 图 × 6 问 × 3 设置）

| 模型 | 总体准确率 | yes 比例 | random | popular | adversarial |
|---|---:|---:|---:|---:|---:|
| 65M 最终多任务模型 | 37.4% | **76.7%** | 21.3% | 31.3% | 18.9% |
| **Qwen2.5-VL-3B + LoRA** | **94.2%** | 24.0% | 97.9% | 94.9% | 97.7% |

关键发现：65M 模型存在严重的 **yes 偏向幻觉**（负样本下仍答 yes），
3B 模型校准良好。这量化了“小模型幻觉更严重”的规模效应，也说明了
为什么幻觉评测必须进基准套件。

## 3. 数据工程：多任务 SFT 数据集

构建了 231,605 条多任务 SFT 数据：

| 任务 | 样本数 | 来源 |
|---|---:|---|
| Caption | 118,287 | COCO2017 train2017 |
| VQAv2 | 100,000 | VQAv2 train2014 |
| OK-VQA | 9,009 | OK-VQA train2014 |
| MMBench MCQ | 4,329 | MMBench en/dev 全量 |

数据画像（`results/data_profile_multitask.json`）：
- 精确重复（同图+同指令）仅 7 条（0.003%）；
- minhash 采样近重复率 0.0016%（15k×100 对，阈值 0.8）；
- 唯一图像占比 51.6%（跨任务同图保留，任务内同图多问题保留——
  多任务对与多问题单图是刻意保留的信号）；
- 数据构建支持 zip 直读与目录直读两种模式，256×256 编码，8–16 线程。

## 4. 最终 VLM：多任务 SFT

从 `pretrain_full_vlm` 基座做单阶段多任务 SFT（batch 32 × 2 epochs，
freeze_llm=1，49 分钟，峰值显存 9.6GB），产出 `multitask_final_vlm`。

### 全基准结果

| 基准 | 最终 65M | 旧最佳 65M | Qwen3B LoRA |
|---|---:|---:|---:|
| 官方 COCO CIDEr | **0.6395** | 0.0067 | 0.8364 |
| 官方 COCO BLEU-4 | **0.2271** | 0.0266 | 0.2566 |
| 官方 COCO ROUGE-L | **0.4723** | 0.2159 | 0.4542 |
| 官方 COCO METEOR | **0.2364** | 0.1529 | 0.2647 |
| VQAv2（2000 题） | **32.8%** | 31.6% | 82.0% |
| OK-VQA（5046 题） | 3.2% | 0% | 38.5% |
| MMBench en/dev 全量 | **26.0%** | 12.0%（200 抽样） | 84.9% |
| POPE 总体准确率 | 37.4% | — | 94.2% |

核心结论：
1. **多任务 SFT 首次让 65M 模型同时拿到强 caption（CIDEr 0.64）与
   VQA（32.8%）**，解决了此前“VQA 提升必然毁掉 caption”的 tradeoff
   （vqa-only SFT 的 caption BLEU-4 曾归零）；
2. 官方 COCO 指标从 0.006 量级拉到 0.64（+110×），逼近 3B 的 7 成，
   首次具备与论文口径直接比较的能力；
3. MMBench 从 12% 提升到 26%（全量 4329 题），任务广度明显改善。

诚实边界：模型严重偏向 COCO 式描述分布；POPE 显示严重 yes 幻觉；
OK-VQA 仅 3.2%（知识短板）。这些如实记录。

## 5. RLHF 升级：强模型 judge 奖励（GRPO v3）

### 5.1 judge 奖励的代理质量分析

用 Qwen2.5-VL-3B 对最终模型 500 条 COCO 预测打分（1–5），与官方指标
做 Spearman 相关：

| 对比项 | Spearman r |
|---|---:|
| judge vs CIDEr | 0.480 |
| judge vs ROUGE-L | 0.478 |
| judge vs 内部 proxy 奖励 | 0.469 |
| judge vs METEOR-exact | 0.425 |
| judge vs BLEU-4 | 0.384 |

结论：强模型 judge 是**合理但不完美**的奖励代理（r≈0.4–0.5），
比 CIDEr 代理更接近人类质量观感，但必须实证其优化是否迁移到官方指标。

### 5.2 GRPO v3（纯 judge 奖励，800 步）

控制变量设计：与 fix2 完全相同的基座（sft_full_vlm）、数据
（grpo_i2t.parquet 5000 条）、group/PPO 超参，唯一差异是把 n-gram +
CIDEr 代理奖励换成 3B judge 打分（映射到 [-1,1]）。自适应 KL 目标
0.08，800 步耗时 25 分钟。

训练观测：judge 奖励从 -0.375 提升到 -0.125（judge 均分 ~2.58 → 2.75），
KL 稳定在 0.096，无 KL 爆炸。

### 5.3 GRPO v3 评测结果：一个 reward hacking 负结果

| 指标 | SFT 基线 | GRPO fix2（n-gram+CIDEr） | GRPO v3（3B judge） |
|---|---:|---:|---:|
| 官方 BLEU-4 | 0.0237 | 0.0266 | 0.0210 |
| 官方 CIDEr | 0.0058 | 0.0036 | 0.0047 |
| 官方 METEOR | 0.1491 | 0.1529 | 0.1464 |
| POPE 总体准确率 | — | — | **0.0%** |
| VQAv2 | 0.0% | 0.0% | **0.0%** |

**诊断（逐样本检查）**：GRPO v3 模型在 POPE 中输出
"As an AI language model, I don't..." 式拒答，在 VQA 中输出
"According to the context provided..." 式冗长对冲，COCO 描述变为
"depicts ... with a grassy area" 式重复啰嗦。根因：

1. 训练数据 `grpo_i2t.parquet` 含安全/合规类样本；
2. Qwen2.5-VL-3B-Instruct judge 对这类"安全腔"回答给出更高分
   （judge 均分确实从 2.58 升到 2.75，奖励被真实优化）；
3. 策略随之漂移成拒答 + 啰嗦风格，任务完成度归零。

**这是 LLM-as-judge 奖励的典型 reward hacking 案例**：judge 奖励的
是"像好 LLM 的回答"，而不是"完成任务"，当训练数据里混入安全样本时，
策略学会取悦 judge 的安全腔。修复方向（记录为后续工作）：
回答格式约束（格式 reward / 采样 mask）、judge prompt 明确任务导向、
训练数据去安全样本、或改用 judge 偏好对（DPO）。

诚实结论：GRPO v3 没有提升任务指标，但它**证明 judge 奖励确实被
优化（judge 分数上升）且 KL 稳定，同时暴露了 judge 奖励的分布外
风险**——这与 5.1 的相关性分析（r≈0.4–0.5）互相印证：强模型 judge
是更强但同样可被 hack 的代理。完整保留了"正代理、负迁移"的证据链。
